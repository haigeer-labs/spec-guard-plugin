# Migration: legacy tracker bridge retirement

## Who is affected

Projects that used spec-guard v0.14.0 or earlier to project capability maps and
tasks into GitHub or GitLab are affected.  The next release removes that mutable
workflow; it does not replace it with another remote tracker client.

## Before upgrading

Choose one manual outcome for every active remote workflow:

1. Complete it with v0.14.0.
2. Mark it closed or abandoned in the tracker using your normal human process.
3. Preserve it as historical work and begin new work through Proposal or the
   local file-backed convention.

Do not delete `.agent/state.json` only to silence a warning.  Keep it, remote
Issues, pull requests, merge requests, archives, and release evidence as the
historical record.

## After upgrading

The plugin emits at most a read-only migration notice when it sees a legacy
GitHub/GitLab state file.  It does not authenticate, inspect remote objects,
select work, alter branches, or modify the file.  Use the local convention for
new local module work, or use the Proposal read-only entry points for candidate
review and promotion proof.

The migration notice is transitional and is scheduled for removal in the minor
release following this retirement release.

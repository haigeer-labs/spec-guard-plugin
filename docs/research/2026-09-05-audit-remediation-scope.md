## 1. 目标与边界

先让现有插件承诺的功能可信、可验证、可恢复，再考虑扩大自动化。定位维持“agent-skills 的项目工作流一致性与能力演进追踪插件”。

本轮保留并完善：模块产物约定、tracker 映射与任务选择、只读阶段/漂移检测、能力历史、并行候选与边界指引。

推荐收缩：现有实验性的 worker 启动、登记、自动汇合和回收写入口，先封闭并提供只读诊断及人工恢复说明。不要在修复 F01/F03 时顺便建完整自动执行器。仅写 experimental 文案不能消除可触达的错误写入。

这是待批准的功能收缩，尚未修改代码。若选择继续提供这些写入口，就必须补齐各自真实执行与异常恢复验收，整改范围与成本会明显扩大，不能以“实验性”豁免。

不纳入：新 controller、SQLite 执行账本、完整 DAG 调度、后台守护、多模型路由、桌面自动建任务/隐藏/回收、能力目录新产品功能。相关提案保留但暂停。

证据分类：“复现”指原审计运行结果；“源码”指代码推导或契约缺口，不冒充真实项目 E2E。P1/P2 沿用原报告，并非所有 P2 都可推迟。

| F10 | P2；不一致 run 复现 | 校验只读账本及所有保留入口 | filename/runId/workerId 不一致明确报错；不得派生新的占用；坏记录保留原样 |
| F11 | P1；源码及现有真实历史 | 修复未来历史摘要，设计既有历史纠错 | 职责/依赖取对应快照；时间有真实来源；完成有交付证据；未知不用 not-started 冒充；不静默重写历史或伪造时间 |
| F12 | P2；上游示例复现 | 修复并列 Build order 兼容 | 线性/并列合法样例通过；重复/未知/循环/逆依赖失败；digest、GitLab、预览等消费者一致；旧摘要迁移不制造假漂移 |

F07 的第一阶段目标是可靠绑定与保守拒绝，不声称实现跨机器强互斥。不能识别其他会话时，不宣传并发安全，也不能随意选择下一条 Issue。若必须新增完整调度或全局锁服务才能满足某种模式，就将该模式明确留在受限范围，而非偷偷扩张。

F11 必须区分“新事件正确”与“旧历史已纠正”。旧数据优先依据原快照追加纠错/派生说明；无法证明的字段显示 unknown 并保留原始记录。仅把归档完成的所有模块强改 completed 不合格。

## 3. 收尾状态，不能混用

- 未处理：只有报告或提案。
- 已修复待验收：代码已改，证据不足。
- 已修复并验证：原反例被拦截、正向行为通过、入口及回归有证据。
- 已缓解并验证：危险能力不可触达、迁移与用户说明验证过；底层功能仍未完成。
- 已接受限制：明确模式/影响/替代路径，由用户批准；不能用于掩盖仍可触发的数据破坏或错误写入。

“暂缓”“未验证”“环境未就绪”都不是通过。收尾报告分别统计修复、缓解、限制和剩余风险，不用一个关闭数制造完整实现的错觉。

## 5. 四端与真实项目验收

矩阵每格必须同时标明功能模式与证据：实现存在、源码/fixture 验证、真实宿主验证、未验证、明确不支持。不能把“有 skill”写成“功能完整支持”。Claude 桌面 Code 模式与 Chat MCPB 单列。

保留功能按 Codex CLI、Codex 桌面、Claude Code CLI、Claude 桌面 Code 模式逐一验证插件版本、实际 cwd、规则加载、命令入口和权限拒绝行为。Chat MCPB 额外验证只读边界。

真实项目验收顺序：

1. GitHub 测试仓库：首次使用 → 同步 → 重复同步/中断恢复 → 两任务顺序开发 → PR → 合并对账 → 历史；再跑旧版升级。
2. GitLab 测试仓库：同样旅程；平面 Issue 关联不冒充原生 sub-issue/阻塞，显式绑定并验证依赖语义。
3. 两个手工创建的不同 worktree：同账号、不同需求及同图不同模块；验证明确绑定或保守拒绝，不能跨模块选任务。此项不要求自动启动两个 Agent。
4. 无认证、离线、插件缺失、未知记录、脏目录、主分支推进：明确暂停/降级，不产生假绿、不清理用户资源。
5. 从实际 release 安装到新会话再验证，不用源码测试替代安装测试。

不能用 GitHub 成功推导 GitLab 成功，也不能用同一 CLI 的成功替代桌面入口验证。若环境无法完成某格，记录未验证并收缩支持声明；若它属于批准的稳定支持范围，则阻塞收尾，不悄悄删掉验收。

真实远端写入前必须确认目标确为测试范围、记录目标身份和预期副作用，不把业务仓库当作可任意重置的 fixture。合并/清理沿用明确授权范围，不因本提案而获得新增权限。

## 6. 最终关闭门禁

- F01–F13 每项都有处置、提交/PR、验证命令、日志/远端证据和残余限制；无对应证据不能标完成。
- 高风险错误写入、串任务、假完成、误回收不存在可触达的未缓解路径；不仅改入口文案，还检查底层脚本。
- 按项目要求运行 validate、phase、verify、Codex adapter 和 smoke 自检；新增相关测试接入常规门禁。运行真实宿主验收另行计数，不混入自检。
- 检查器有正反例；旧行为应失败、正常串行应通过；新约定、模板、bridge、hook、校验器同时一致。
- CI 有实际运行证据；若云端环境仍不可用，明确由用户接受有记录的替代发布门禁，不能宣称云 CI 通过。
- README、设计/兼容文档、命令帮助和 CHANGELOG 与实际支持范围一致，明确不支持完整自动并行执行。
- 版本正确递增，包内容可追溯到发布提交；安装内容核对插件文件而非单看仓库 HEAD；新会话实际加载验收通过。
- 用户审阅收尾报告，确认已缓解/接受限制列表；重新评分沿用原维度，同时注明功能收缩，不能靠删除低分能力来宣称完整性提高。

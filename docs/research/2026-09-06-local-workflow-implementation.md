## 已实现

- 选择性复用 `886daf7` 的共享本地阶段判据，补上 issueTypes 类型检查。phase/verify 对合法本地阶段显示模块与 tracker 未激活；非法 state、缺产物或遗留门禁仍被检查。
- 现有 setup-convention 增加本地上下文分支。默认展示 state 前后差异；具体范围已获确认后用 `--confirm` 原子写入；`--dry-run` 不写。拒绝覆盖远端映射、disabled state、错误 tracker 或非法产物。本任务自己的 state 就通过该入口创建、再推进到单一模块 `workflow-checkpoint-preview`；initiative.issue=null、modules={}。
- GitLab Python 同步入口和旧 shell issue/MR 写入口在认证前拒绝本地阶段；binding、next、deliver 的现有入口保持字段守卫。普通无字段流程保留原有门禁。
- verify 的图外 spec 使用共享历史 schema、摘要和能力图解析，区分内容已验证、仅归属可证、无归属。内容不符、坏账本或越界证据不能降级为宽松豁免。
- 本地生命周期从能力图取得复制/清理集合，保存已有 spec/plan，并在记录完成、删除当前产物前验证新 checkpoint。核验仅针对本次快照，避免无关旧 checkpoint 阻断本次操作；旧历史完整性仍由 verify-history 检查。普通空 state 的旧兼容用例保留。
- 检查点契约唯一正文位于 `plugins/spec-guard/references/workflow-checkpoints.md`。命令、三个 skill、六种模板及 hook 的短路径事实接入它；覆盖设计、计划、实现、失败、交付、拒绝/未知、取消/暂停。已有授权不重复询问，普通“继续”不能恢复暂停 initiative。

## 检查点场景审查

| 场景 | 共享规则要求 | 本轮证据层次 |
|---|---|---|
| 设计完成进入计划 | 明确确认范围与计划路径，已有实施授权直接承接 | 本会话实际承接“继续”，创建自己的 spec/plan |
| 计划进入实现 | 预告首个测试/实现切片和停点 | 本会话预告并实施本地上下文切片 |
| 实现进入验证 | 报告完成范围与真实命令，不预报通过 | 本会话预告固定源码后跑五项检查 |
| 验证失败 | 报告失败，定位、修复、复验，不降标准 | 生命周期兼容失败按此处理 |
| 交付前远端操作 | 列出仓库、对象、写入内容与授权范围 | 规则/入口审查，未执行远端交付 |
| 权限拒绝或结果未知 | 说明来源，先只读核对，不盲重试写入 | 规则/入口审查，未伪造宿主验证 |
| 用户取消或暂停 | 保留成果、旧预告失效、不扩大“继续” | 暂停的自动并行 initiative 保持未恢复；完整取消交互未另启动宿主评测 |
